# 热点追踪库

## 写作前热点检查（每次选题必做）

1. 搜索最近 7 天与文章领域相关的热点。
2. 按下方渠道清单逐个扫一遍，记录到热点登记表。
3. 相关度 ≥4 星的热点，优先级高于常青选题。
4. 热点必须融入选题和开头：选题阶段确定角度，开头 100 字内接入热点事件、数据或争议。
5. 无法核实来源的热点，一律标注"需核实"；引用热点必须带时间和出处。

## 渠道清单（8 个）

| 渠道 | 看什么 |
|------|--------|
| 微信搜一搜 | 公众号生态在讨论什么、搜索热词、热点榜 |
| 新榜 | 各领域爆款文章、公众号榜单、选题风向 |
| 清博 | 公众号/短视频热文榜、传播数据 |
| 百度指数 | 话题热度趋势与地域人群画像 |
| 微博热搜 | 大众讨论角度、争议点、情绪走向 |
| 知乎热榜 | 深度讨论、专业视角、高赞论点 |
| GitHub Trending | 开发者圈新项目、AI 编程/Agent 新工具 |
| Product Hunt | 新产品、AI 工具、独立开发动向 |

用法提示：微信搜一搜、新榜、清博看"读者在看什么"；微博、知乎看"读者在吵什么"；GitHub Trending、Product Hunt 看"下周该写什么"；百度指数验证热度是上升还是回落。

## 分领域信息源

- AI 与大模型：官方博客、官方账号一手发布、发布会实录
- AI 编程与 Agent：Cursor、Claude Code、OpenAI Codex、主流 Agent 框架更新日志
- 图生视频：Runway、Kling、Seedance、Sora 等官方发布
- 插件与 APP 开发：官方 SDK 文档、开发者社区、GitHub / Product Hunt
- PR / AE：Adobe 官方 What's New 页面、版本更新日志

## 热点登记表格式

| 日期 | 事件 | 来源 | 相关度(1-5星) | 可用角度 | 核实状态 |
|------|------|------|---------------|----------|----------|
| YYYY-MM-DD | 一句话说清事件 | 链接或出处 | ★★★★☆ | 用在标题还是开头 | 已核实 / 需核实 |

## 热点融入规则

1. 时效判断：24-72 小时内发布蹭热点文章效果最好；超过 7 天的热点只作背景素材，不再作主选题。
2. 选题融合：热点不是硬贴，必须能回答"我的读者为什么要在乎这件事"。
3. 开头融合：首段用热点事件、数据或争议切入，第二句马上接到读者的痛点或利益上。
4. 过时复核：发布前复核版本号、价格、功能是否已变化；易过时的信息标注"截至 YYYY-MM"。
5. 风险红线：无法核实的热点不写，或明确标注"需核实"；不传未经证实的爆料。

## 热点说明输出格式（每篇文章必附）

- 事件：一句话说清发生了什么
- 时间：发生或发布时间
- 来源：可核实的链接或官方出处
- 与读者的关系：为什么值得他们花 3 分钟

## 环境限制说明

当前 Codex 环境网络受限，部分渠道（微信搜一搜、新榜、清博等）无法直接抓取。处理方式：

1. 能访问的渠道直接查；不能访问的渠道由用户提供链接、截图或粘贴内容。
2. 用户喂料格式：链接 + 一句话说明想用它的哪个角度。
3. 凡未能亲眼核实的渠道数据，一律标"需核实"，不在正文当确定事实引用。

## 追踪节奏

1. 每周汇总一次"本领域值得写的 3 件事"。
2. 热点价值判断公式：新（24-72 小时内）× 与读者相关 × 可验证。
