# 综合质检表

## 定位

本表是唯一的评分与重写标准。原来的「自检 8 项」「去 AI 感自检 8 项」「10 项评分表」已全部并入本表，禁止再按多套清单重复校验，也不存在"按 A 清单过了、按 B 清单挂了"的情况。

## 使用时机

每篇文章初稿完成并经查重改写后打分，只打这一次分。

## 评分必须落盘，不接受口头分数

1. `python quality/qa_report.py init --article articles/<slug>/article.md`（跑硬指标，生成骨架）
2. 按本表逐条打分，写成 `soft.json`
3. `python quality/qa_report.py apply --slug <slug> --scores <soft.json>`（校验通过才落盘）

产物是 `articles/<slug>/qa-report.md`，抽查时看得到每一条扣分理由。硬指标维度由脚本判定，模型填报会被拒绝。详见 `references/public/stage-gate.md`。

## 评分规则

- 4 个维度，每维度 0-100 分，总分 = Σ(维度分 × 权重)，满分 100。
- 权重：事实准确 30%、风格规范 30%、去 AI 感 20%、硬指标 20%。
- 「硬指标」维度必须以 quality/check_article.py 的实际输出为准（查重 + 违禁词 + 配图资产），禁止凭感觉填写。
- 打分必须给理由：每个维度写一句"为什么给这个分"，禁止无理由打分。
- 总分低于 85 分：触发增量重写，只重写得分最低的扣分段落，其余内容保留；每轮重写后重新运行 check_article.py 并重新打分。
- 段落级重写上限 2 轮：仍低于 85 分时停止重写，输出当前最优版本，标注「需人工介入」并说明卡住的段落与原因。禁止没有结构性理由就全文重写。

## 维度 1：事实准确（权重 30%）

- 数据、产品、版本、价格有可核实来源（40 分）：全部可追溯给满分；主体准确但个别缺源 6-8 折；关键数据无来源或与最新公开信息矛盾不及格。
- 无法核实的已明确标注「需核实」（30 分）
- 案例、引用与来源一致，无编造（30 分）

## 维度 2：风格规范（权重 30%）

- 选题价值（15 分）：戳中目标读者真实痛点，有明确转发或收藏理由；自嗨选题不得分。
- 标题点击欲（15 分）：24 字以内，情绪钩子 + 具体利益，正文兑现标题承诺，不做标题党。
- 开头钩子（10 分）：前 100 字内有场景、冲突或反常识结论。
- 信息密度（20 分）：每 300 字至少 1 个可记忆的点，删掉任何一段都损失信息，不注水。
- 可执行性（10 分）：步骤完整，读者知道第一步做什么、用什么工具、预期结果。
- 情绪共鸣与传播钩子（15 分）：至少一处"说的就是我"，至少一处让人想转发。
- 配图相关度（5 分）：3-5 张图，每张直接服务当前段落内容。
- 排版易读（10 分）：段落不超过 4 行，小标题清晰，重点加粗，手机可读。

## 维度 3：去 AI 感（权重 20%）

- 无套话开头、空洞总结、机械分点（40 分）
- 第一人称与对话感自然，且不超频次上限：口语词每篇最多 1 次，对话感每 500 字最多 1 处（30 分）
- 句子长短交替、段落长短不一（15 分）
- 通读像真人聊天："换成真人不会这么说"的句子为零（15 分）

## 维度 4：硬指标（权重 20%，机器输出，模型不得填写）

以下结果由 `quality/qa_report.py` 直接从 `quality/check_article.py` 采集并写入报告：

- 查重：13 字片段重复率 <25% 且最长连续重复 <13 字（40 分；任一项 FAIL 本项 0 分）
- 违禁词：banned-words.txt 高风险词 0 命中（40 分；命中即 0 分；中低风险不扣分，列入待确认）
- 配图资产：正文图片与 meta.cover 全部真实存在（20 分；缺失即 0 分）
- 全部 PASS = 100 分。

## 打分输出格式

```
## 综合质检表

| 维度 | 权重 | 得分 | 加权 | 理由 |
|---|---|---|---|---|
| 事实准确 | 30% | x | x | 一句话理由 |
| 风格规范 | 30% | x | x | 一句话理由 |
| 去 AI 感 | 20% | x | x | 一句话理由 |
| 硬指标 | 20% | x | x | check_article.py 输出摘要 |
| 总分 | | | xx/100 | |
```

软指标三条维度必须各自给出扣分明细（扣分项、满分、实得、不少于 10 字的理由），维度得分必须与明细合计一致，否则 `qa_report.py` 拒绝落盘。

## 重写报告格式

总分低于 85 时，重写后必须附上：

```
## 重写说明（第 n 轮 / 上限 2 轮）

- 维度 x（原 x 分 → 现 x 分）：改了什么、为什么这么改
```

2 轮后仍不达标时，附：

```
## 降级说明

- 最终得分 xx/100，未达标维度：xxx
- 已输出当前最优版本，需人工介入。
```
